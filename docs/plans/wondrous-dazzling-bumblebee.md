# daily レポート改修プラン（daily-research 文体層 + edge line 全面改修 + edge-frontier 規準）

## Context

edge-frontier の daily レポートが「題材は面白いのに意味不明」という状態。mondo セッションでの診断:

- **規準の層**: edge-frontier は性質の違う desire-frontier（証言収集）を雛形に作られ、
  検証規律（一人称・真正性・「迷ったら載せない」）を継承した。目的はアイデア収穫
  （盗める手筋 + 強度の相場観）で、偽陽性が安く偽陰性が高い**逆の経済**。検証規律は
  失敗 post-mortem を系統的に選好する
- **読者モデル・文体の層**: 直近 4 本の初見通読で 6 病型を同定 —
  ①逆リード（repo・台帳から始まる）②幽霊参照（「指針(b)」「種別C」など座標のみ）
  ③一文多命題 ④認識論実況（「断定しない」「本 run で検算」の頻発）⑤造語積層
  ⑥「学び」枠の台帳運用ノート化。他 line（desire/akc/contemplative）も同病を確認
- **発生源は共通層**: 共通プロトコルは「読者は運用者一人、朝読むだけで完結、前提知識ゼロ」
  と正しく書いているのに、テンプレの「冒頭に結論 = repo への含意の要約」が①を、
  テーマ選択ゲート「どの ADR / task に使えるかを固有名詞で」が②⑥を、
  大原則 5「事実と解釈を分ける」の運用が④を、制度として生産している

ユーザー決定: 器は**物語主体**（事件から始め「盗める手筋」必須節）/ スコープは
**レポート + 規準の両方** / 自己参照は**本文から全面排除** / 横展開は
**文体層のみ全 line、節構成変更は edge のみ**。

## 改修 A: daily-research 共通層（全 7 line に効く文体層）

### A-1. `prompts/repo-research-protocol.md`（Step 5 に文体規律を追加、大原則 5 を修正）

Step 5 に「文体規律（6 項目）」を追加:

1. **第一文は外部の出来事**から。repo・台帳・過去レポート・過去 run の仮説から始めない
2. **一文一命題**を基本にし、挿入句の入れ子・文中太字の多用をやめる
3. 内部文書（ADR / playbook / 過去レポート）に触れるときは**参照先の中身を本文で
   1 行要約して運ぶ**。座標だけの参照（「指針(b)」「種別C」「N 日前に立てた仮説」）を
   書かない。過去 run との照合・失効条件の判定は state 更新（Step 6）にのみ書き、
   本文には書かない
4. 事実 / 解釈 / 二次の区別は**文の形**で行う（「〜と報じられている」等）。括弧の
   認識論注記（「断定しない」「本 run で検算」「解釈」）は 1 本あたり 2 箇所まで
5. playbook 語彙・造語を本文で未定義のまま使わない
6. repo の自己紹介の再演は背景相当の説明 2 文まで

大原則 5 の末尾に「区別は書き方で示す — 括弧注記の列挙で示さない（上限は Step 5）」を追記。
Step 2-2 の「レポート本文に書くのは今日の主題に関係する分だけ」を「本文には書かない。
state 更新にのみ記録する」へ強化（自己参照の全面排除）。

### A-2. `templates/report-template.md`（記述規律の書き換え）

記述規律 1「冒頭に結論: 今日の外部の動きと、この repo への含意の要約」を
「冒頭は**外部の出来事**から。含意で書き始めない」に変更。記述規律 3 の
事実/解釈の指示に A-1 の括弧注記上限を反映。節構成（結論/何が起きたか/背景/含意）は
研究 line 用にそのまま残す。

### A-3. `prompts/clarity-review-protocol.md`（呼2 に 6 病型を教える）

つまずき定義に 6 病型を明記し、span 編集で直せるもの（一文多命題の分割、
認識論注記の削減、幽霊参照への 1 行要約の補い — 事実の追加にならない範囲）を
修正対象に加える。禁止事項（数値・固有名詞・frontmatter・機会メモ/ソース節）は維持。

## 改修 B: edge line の節構成と目的（daily-research 側）

### B-1. 新テンプレート `templates/report-template-edge.md`（新規作成）

frontmatter は共通テンプレと同一。節構成:

```
# タイトル（読ませる見出し — 現行の質を維持）

## 何が起きたか      ← 本体。事件から開始。異常な数字と当事者の生の引用を主役に。
                       背景説明は物語に織り込む（独立節にしない）
## 盗める手筋        ← 必須 1〜3 個。「自分の harness / 運用に移植するなら」の粒度。
                       手筋が無い日は「相場観の更新」1 行でも可
## 検証メモ          ← 任意・3 行以内。到達確認の結果のみ。認識論の実況は書かない
## 機会メモ          ← 固定（機械検査 ctl-016 対象。現行形式のまま）
## ソース            ← 固定（同上）
```

「結論」「背景」「この repo への含意」は edge から廃止。規準への示唆が生まれた日は
末尾に `（台帳メモ: …）` 1 行のみ許可（ingest の「メモ」節と規準見直し run の入力）。

### B-2. config.toml `[tracks.edge]` の focus 書き換え + template 指定

focus を目的から書き直す:

- 目的: 「朝の読者（著者本人）が新しい AI 活用のアイデア — 移植できる手筋、
  強度の相場観 — を得る」。レポートの主役は物語と手筋
- 入場の経済を反転: 「手筋か相場観が盗めるなら載せる（迷ったら載せる）」。
  一人称・why 要件を「手筋が具体的に読めること（三人称・二次でも可、
  未検証は [unverified] 明示）」へ緩和
- 新ツール条項の付け替え: 「ツール紹介一般は対象外だが、**常識外の使い方**を
  されているツールは対象。平均的 Tips への劣化は禁止」（守る対象を台帳の純度から
  手筋の具体性へ）
- 崩壊系の再定義: post-mortem 待ちをやめ「限界値の観測（どのパラメータをどこまで
  上げたら壊れたか）+ 突破事例内の壊れかけ徴候」を拾う
- 維持: 規模単独 NG、発見ノルマなし、自然発生 > 製造の優先
- テーマ選択（共通 Step 3 の問 3）の edge 解釈を focus 内に明記:
  「使い道 = 盗める手筋 or 相場観の更新を 1 行で言えるか」（ADR 固有名詞ゲートの置換）

per-track テンプレート機構を追加: `[tracks.edge]` に `template = "templates/report-template-edge.md"`
（省略時は現行共通テンプレ）。

### B-3. スクリプト対応（per-track template）

- `scripts/lib/dr_pipeline.py`: `[tracks.<x>]` schema に optional `template` を許可し、
  `line-brief`（または新 cmd）で解決済みパスを出力。`ARTICLE_SECTIONS = ["機会メモ"]` と
  `## ソース` hard check は新テンプレでも両節が残るため**変更不要**
- `scripts/daily-research.sh`: `$TEMPLATE` の読込を track の template 指定で切り替え
  （235-261 行付近の LINE_PROMPT 組み立て）
- `tests/` の bats / `dr_pipeline_test.py` に template 解決の最小ケースを追加

### B-4. `state/edge/playbook.md` の刈り込み（615 行 → 運用知のみ）

毎朝読まれる第二プロンプトであり造語（階梯・分母・逆選択…）の発生源。
- 残す: 検索の作法・二次汚染の警告・venue ごとの探し方（運用に直結する行）
- 移す: 台帳設計に効く観測・概念の輸入・仮説群 → `edge-frontier` 側に
  `docs/notes/criteria-review-input.md`（新規、規準見直し run の入力置き場）として退避
- state は gitignore なので直接編集でよい。全面書き直し禁止の規約は「delta 更新」の
  対象が run であって人間の棚卸しには適用しない旨を編集コミットメモに残す

## 改修 C: edge-frontier 規準（このリポジトリ）

### C-1. `README.md`

- 「入場条件と境界」節を B-2 と同文になるよう書き換え（経済反転・新ツール条項・
  崩壊系再定義・[unverified] 許容）。正本は README、config focus はそれの要約と明記
- 「観測ループ」節の「事例を物語として解説する」に新節構成（何が起きたか/盗める手筋/
  検証メモ）への参照を 1 行追記

### C-2. `scripts/ingest-protocol.md`

- 「入場条件」節を README 新版と同期（「迷ったら載せない」→「手筋・相場観で判定。
  [unverified] は付けて載せる」）
- 手順 4 のメモ密度指定「how / なぜ / 何が起きた / 人間側」に「盗める手筋」を追加
- 型 4 分類・追記のみ・fact-checker ゲートは維持（無人 commit の安全機構は変えない）

### C-3. 決定の記録

daily-research `docs/adr/` に次番号の ADR を 1 本（adr-writer skill 使用）:
「レポートの読者契約を著者本人に固定し、文体層を共通プロトコルへ、edge を
手筋収穫型に改修」。ADR-0014 の Review-when（2026-08-30「7 日分通読して構造を見直す」）
への応答であることを Context に記載。edge-frontier 側は README の Status 節に 1 行追記。
