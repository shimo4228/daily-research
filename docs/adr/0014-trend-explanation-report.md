# ADR-0014: レポートを「動向解説 + repo への含意」へ単純化し、対立的フレーミングを撤去する

## Status

Accepted (ADR-0008 の目的関数と ADR-0009 の提案禁止範囲を修正、ADR-0010 決定 3・6 と ADR-0013 失効条件 1 の `theme_rank` 観測を supersede)

## Date

2026-08-22

## Context

2026-08-22、運用者は「レポートのスタンスがややこしすぎて読みづらい。前提を崩したり反証する方向ばかり。改修を重ねすぎてプロンプトがややこしくなった」と観測した。

一次資料で確認すると、「外部の事実」を「repo の立場との位置関係の議論」へ変換する圧が 3 層に同じ語彙で複製されていた:

1. **プロトコル** `prompts/repo-research-protocol.md` — 目的関数「repo の前提・問い・立場を**動かす**外部の動き」(ADR-0008/0009)、裏付け (corroboration) 禁止、Step 3c 反証プレッシャー、Step 5 前提挑戦パス (ADR-0010)
2. **テンプレート** `templates/report-template.md` — 記述規律 3 (反対材料必須) と 4 (定点観測の網羅記述 + 自分の過去主張の「反故」再検証)
3. **config.toml 全 7 line** — `focus` の定型句「前提・問いを動かす状況判断 — … / 反証」、`scoring_criteria` (影響度 45 「裏付けの追加は影響ではない」 / 反証性・前進性 30) の逐語コピー、`general.goal` も同文。`line-brief` が weight 付き文字列として毎朝注入していたが、weight は ADR-0010 が Likert 採点を廃した後も誰も集計していなかった

実例 `2026-08-22_aap_accountability-aggregation-not-distribution.md` (約 7,000 字) は、GCC が AI 生成コードを禁止し Linux が `Assisted-by` を要求するという単純な事実を「これは反証ではない。効くのは別の場所だ——留保した問いが別の論理で埋まっていた」型の二重否定で語り、主題と無関係な中国標準・Ohio 法案・Colorado 規則の定点観測を本文にダンプしていた。`edge` line の focus (ADR-0013、2026-08-20) は既に「反証を repo の再審の主題にしない」と個別に押し返していた — 同じ症状への対症療法で、根は 3 層に残っていた。

ADR-0008/0009 の前提は「研究 run は運用者の framework を裏付けに行く (corroboration failure) のが最大リスク」だった。実害は逆方向 — 反証過多で読めない — に出た。

## Decision

1. **目的関数**: 「この repo に関係する外部の動向を 1 つ選び、何が起きたか・なぜ重要か・この repo にどう使えるかを、前提知識ゼロで読める解説レポートとして届ける」。レポートの主語は外部の出来事。repo の立場への賛否・位置関係の議論を主題にしない。発見ノルマなしは維持。
2. **裏付け禁止・反証義務・前提挑戦パスを撤去する**。残す認識規律は「一次ソースで確認した事実と書き手の解釈を分けて書く」1 行のみ。裏付け方向のレポートが出ても許容する (読めて有用なら良い)。
3. **定点観測の本文記述義務を外す**。Step 2 diff パスと `watched-sources.md` / `playbook.md` の更新はテーマ発見の入力として維持。「変化なし」の列挙と過去主張の反故検証は本文に書かない。
4. **テーマ選択を 3 問に簡素化し `theme_rank` を廃止する**: 候補 2〜3 件を「新規か / 一次ソースに届くか / repo のどこに使えるか固有名詞で言えるか」で選ぶ。反証プレッシャー・self-deepen・verdict・frontmatter の `theme_rank` を消す。`/dr-review` の theme_rank 分布集計も廃止。
5. **`scoring_criteria` を config と `line-brief` から削除する**。判断基準はプロトコルの 3 問に一本化し、line 固有の関心は `focus` だけで表す。
6. **構造と長さ**: 推奨 4 節骨格「結論 (3〜5 文) → 何が起きたか → 背景 (初見向け、短く) → この repo への含意」+ 固定 2 節 (機会メモ / ソース)。本文 3,000 字を目安とし、**機械 lint は置かない** (Goodhart 回避)。lint は `body_chars` を記録するだけ。
7. **含意の範囲**: どの ADR / task / open question / 文書にどう使えるかを平文で書いてよい。承認要求・「〜すべき」・手順列挙は引き続き禁止 (ADR-0009 の禁止を承認要求に絞って維持)。
8. **改修方式**: プロトコルとテンプレートは白紙から短く書き直した (176 行 → 125 行)。機構との配線 (Step 1 文脈読込 / Step 2 diff / citation ゲート / 自己汚染ガード / repo read-only / Bash 不可 / state 更新 / 完了報告) は移した。呼2 clarity プロトコルは `theme_rank` 文言の削除以外そのまま。

## Review-when

- **2026-08-30**: 2026-08-23 以降の 7 日分 (約 14 本) を運用者が通読し「最後まで読めたか / repo に使えたものがあったか」を主観判定する。読めなければ本 ADR の構造 (4 節骨格・3,000 字) を見直す。
- **裏付けだけのレポートが 1 週間に 3 本以上出たら**: 決定 2 の「事実と解釈の分離」規律を強める (反証義務の復活ではなく、解釈の根拠明示の強化)。
- **`body_chars` の 3,000 字超過が常態化したら**: プロトコル Step 5 の長さ指示を見直す (lint 化はしない)。

## Alternatives Considered

- **目的関数を残し、書き方だけ平易にする (メタ記述の禁止を追加)**: 改修最小だが、「動かす」目的関数と反証義務が残る限り、位置関係の議論が主題になる根因は消えない。禁止の累積がまさに今回の症状。棄却。
- **repo の次アクションに直結する材料だけの実務ブリーフ**: 最も短いが、ADR-0009 の「読み物」方針を捨てることになり、承認待ち todo 化の再発リスクがある。棄却。
- **裏付け禁止だけ残す (Goodhart の最低線)**: 「支持する」方向の読みを禁じると、事実の解説に「これは裏付けではない」型の留保が戻る。事実と解釈の分離で代替できる。棄却。
- **反証を「あれば書く」任意項目に格下げ**: 任意でも項目があると模型は埋めに行く (記述規律 3 の実績)。棄却。
- **`theme_rank` を残して時系列を守る**: 意味 (T2 「動かすか」) が変わるので比較は壊れる。ADR-0010 の評価計画 (4 週後の分布判定) は 9 日で打ち切りになるが、観測された実害の方が重い。棄却。
- **既存プロトコルを編集で削る**: 箇条書きで削ると「禁止の累積」という構造が残る。白紙から短く書く方を選んだ。

## Consequences

- レポートの主語が repo の立場から外部の出来事に戻り、二重否定と留保が構造的に減る。定点観測ダンプが消えるので長さが下がる。
- 対立的フレーミングが 3 層から同時に消えるので、`edge` のような line 単位の対症療法は不要になる。
- corroboration failure (ADR-0008 が引用した PseudoBench の失敗様式) への防御は「事実と解釈の分離」1 行に弱まる。許容したトレードオフ — 裏付け方向に寄った場合は Review-when 2 で検出する。
- ADR-0010 決定 6 と ADR-0013 失効条件 1 の `theme_rank` 観測は失効。`/dr-review` は `body_chars` と主観判定で代替する。
- 旧プロトコル・テンプレートは git history で復元できる。
- `config.toml` は gitignore のため、運用者のローカルでの書き換えが本 ADR の前提 (同 commit で実施済み、退避コピーは scratchpad)。
