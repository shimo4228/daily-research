# ADR-0016: 発見を中心に据えた日刊号へ再編する

## Status

Superseded by [ADR-0017](0017-three-line-window-content-states-and-verification-pass.md)（2026-09-14、Decision 5 を supersede）。8 日運用（2026-09-07〜14）の結果、運用者は通読の印象として「無関係な話題ばかり」と評価し、Decision 5 で退役させた旧設計の適用範囲を復活させた。Decision 1〜4 の discovery 号は supersede ではなく実装ごと退役（記録 7877a11、削除 48c8908）。本記録は当時の判断として保存する。

## Date

2026-09-06

## Context

運用者は、リサーチ方法を何度も変更してきたものの、最近のレポートには興味を惹かれるものが少ないと述べた。題材の飽和に加え、蓄積した文脈と制約が探索を収束側へ傾けている可能性を挙げ、レポートのあり方からの再編を求めた。文脈過多が原因という説明は運用者の仮説であり、測定で確かめた結果ではない。

従来の `prompts/repo-research-protocol.md` は repo の課題と蓄積を起点に題材を選び、repo への含意を届ける設計だった。今回の承認済みプランは、即時の使い道を選定の条件とせず、次に考えたいこと・試したいことを発見する読書体験を目的とする。

## Decision

1. **repo 輪番を廃止し、探索と編集を独立した Opus セッションへ分ける。** 探索には短い読者紹介と日付だけを渡し、候補 6〜10 件を目安に外部を調べる。repo の課題・ADR・playbook・過去記事は渡さない。編集には探索素材、読者紹介、直近 30 日の配信済み記事索引を渡す。編集者は追加調査し、候補を捨てる・組み合わせる・主役を替える権限を持つ。
2. **一日一号を届ける。** 通常号は主役 1 本と短報を通常 2 件、最大 3 件とする。主役は日本語 1,800〜2,600 字、短報は各 200〜400 字を目安とし、文字数や候補数を合格条件にしない。主役が弱ければ短報号、短報も弱ければ休刊とする。確認した事実と推測を文章で区別し、出典数のノルマを置かない。
3. **リサーチ実行を隔離する。** 専用作業ディレクトリから `--safe-mode` で起動し、モデルのツールを WebSearch と WebFetch に限定する。構造化 JSON を標準出力から受け取り、検証後の保存と履歴更新はプログラムが担う。休刊記録は非公開とし、wiki に取り込まない。自動実行モデルは Claude を継続する。
4. **過去の蓄積をアーカイブとして残す。** 旧 playbook を自動入力や自動フィードバックに使わず、読者紹介の更新は本人が確認した反応に基づく。探索と編集にそれぞれ実行上限を設ける。
5. **旧設計の適用範囲を退役させる。** 新経路では [ADR-0001](./0001-research-repo-feedback-engine.md)・[ADR-0002](./0002-reports-as-frontier-diff.md)・[ADR-0003](./0003-cross-line-knowledge-cycle.md) の repo 中心の目的、[ADR-0008](./0008-per-repo-in-context-research.md) の in-context 実行、[ADR-0009](./0009-explanatory-report-and-brief-retirement.md)・[ADR-0014](./0014-trend-explanation-report.md) のレポート目的を置き換える。[ADR-0010](./0010-rotation-and-two-tier-eval.md) の輪番と二段階評価、[ADR-0011](./0011-daily-line.md)・[ADR-0012](./0012-desire-back-to-rotation.md)・[ADR-0013](./0013-edge-daily-line.md) の daily line 運用、[ADR-0015](./0015-reader-contract-style-rules-and-edge-idea-harvest.md) の固定末尾節と edge 固有契約、[ADR-0006](./0006-self-improvement-loop-human-consumer.md) の旧 lint・レビュー機構を新経路には適用しない。過去の記録自体は残す。

## Alternatives Considered

### 現行設計を継続する

運用者がレポートのあり方からの再編を求めたため、現行の repo 中心設計を継続する案は採用しない。

### 選定ルールを追加する

制約の蓄積が収束を招いているという仮説に対し、さらに選定ルールを加える応答は採用しない。探索へ渡す文脈を減らし、編集段階で選ぶ構成に変更する。

### 自動実行を Astra へ移す

承認済みプランは設計の見直しと実行モデルの変更を分け、自動実行には Claude を継続するとした。今回の変更には含めない。

## Consequences

### Positive

- repo の即時の使い道を越えた題材を探索できる。
- 編集者が題材の選択と追加調査を担当し、一号全体を組み立てられる。

### Negative

- 届く発見に、すぐに使える実用性がない場合がある。
- 二つの Opus セッションの実行上限が、探索と追加調査の深さを制限する。

### Neutral / Follow-ups

- 面白さが改善したかは、初回の実行と運用者の通読で確認する。設計変更だけで改善を確認済みとはしない。
- 旧 ADR には現在の判断への参照を付け、元の判断内容は維持する。

### Review-when

- 運用開始から 7 日後に、「続きを読みたくなった記事」「新しく考え始めたこと」「繰り返しと感じたもの」を運用者に確認する。
- 関心を惹かない状態が続く、または文脈の隔離が必要な理解を妨げる場合は、読者紹介・探索経路・編集判断を再検討する。
