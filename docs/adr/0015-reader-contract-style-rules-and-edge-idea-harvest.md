# ADR-0015: レポートの読者契約を文体規律として共通化し、edge line を手筋収穫型へ改修する

## Status

Accepted (ADR-0014 Review-when 第 1 項の早期発火への応答。ADR-0014 の 4 節骨格は研究 line で存続、edge line のみ節構成を置換)

## Date

2026-08-27

## Context

2026-08-27、運用者が edge line の直近 4 本 (2026-08-24〜27) と他 line 3 本 (desire 08-25 / akc 08-26 / contemplative 08-27) を初見読者として通読し、「題材は面白いがレポートが意味不明」という観測から 6 つの失敗型を同定した (以下は本 ADR の呼称):

1. **逆リード** — 第一文が外部の出来事でなく repo・台帳・過去レポートから始まる
2. **幽霊参照** — 「指針(b)」「種別 C」「N 日前に立てた仮説」のような座標だけの内部参照
3. **一文多命題** — 挿入句の入れ子・abstract 密度の圧縮文
4. **認識論実況** — 「断定しない」「本 run で検算」等の括弧注記が 1 本あたり 5〜8 箇所
5. **造語積層** — playbook で育った語彙の未定義使用
6. **「この repo への含意」節の台帳運用ノート化**

発生源は書き手の癖ではなく共通層の構造規定にあった。共通プロトコル (`prompts/repo-research-protocol.md`) は「読者は運用者一人。朝、読むだけで完結」「前提知識ゼロで読める」と正しく宣言している ([ADR-0014](./0014-trend-explanation-report.md) 決定 1) のに、テンプレートの記述規律 1「冒頭に結論 = 今日の動きと repo への含意の要約」が①を、テーマ選択 Step 3 の「どの ADR / task / open question に使えるかを固有名詞で言えるか」が②⑥を、大原則 5「事実と解釈を分けて書く」の括弧注記としての運用が④を、それぞれ制度として生産していた。呼2 の clarity レビューは span 編集 1 周のみで、これらの構造病に届いていなかった。

edge line 固有の問題が重なる。edge line ([ADR-0013](./0013-edge-daily-line.md)) は desire-frontier line を雛形に作られ、証言収集のための規律 (一人称必須・「迷ったら載せない」) を継承していたが、edge-frontier repo の目的はアイデア収穫 (運用者が移植できる手筋と強度の相場観を得る) であり、偽陰性が偽陽性より高くつく逆の経済である。検証可能性を要求する規律は、公開の中間生成物を残す失敗事例 (post-mortem) を系統的に選好し、成功者の一次記録を落とす向きに働いていた。加えて edge の `state/edge/playbook.md` は 615 行に育ち、うち 4 節 (台帳設計・概念の輸入・一人称の読み方・反対材料) は毎朝の運用知ではなく規準見直しの判断材料で、②⑤の語彙の供給源になっていた。

ADR-0014 の Review-when 第 1 項 (2026-08-30 に 7 日分を運用者が通読し「最後まで読めたか」を主観判定、読めなければ構造を見直す) は、この通読により早期発火した — 判定は「読めない」。

## Decision

1. **全 line 共通の文体規律** を `prompts/repo-research-protocol.md` Step 5 に 6 項目追加する: (1) 第一文は外部の出来事から書く — repo・台帳・過去レポート・過去 run の仮説から書き始めない (2) 一文一命題を基本とし、挿入句の入れ子・文中太字の多用を禁止する (3) 内部文書に触れるときは参照先の中身を本文で 1 行要約して運ぶ — 座標だけの参照は禁止する。過去 run との照合・失効条件の判定は Step 6 の state 更新にのみ書く (Step 2-2 も同旨に強化) (4) 括弧の認識論注記は 1 本あたり 2 箇所までとし、区別は文の形で示す (大原則 5 に同旨を追記) (5) playbook 語彙・造語の未定義使用を禁止する (6) repo 自己紹介の再演は 2 文までとする。`templates/report-template.md` の記述規律 1 は「冒頭は外部の出来事から」に変更する。節構成 (結論/何が起きたか/背景/この repo への含意) は研究 line 用に維持する。
2. **呼2 clarity レビューの検出対象に②④を追加** する (`prompts/clarity-review-protocol.md`)。幽霊参照 (本文の他所にある説明での補いか、削って文が立つなら削除) と認識論注記の過多 (3 箇所目以降の削除。事実・数値は不変) を span 修正の許可操作に加える。
3. **per-track テンプレート機構を導入する**。`[tracks.<x>]` に optional `template` キー (project 相対パス、省略時は `templates/report-template.md`) を追加し、`dr_pipeline.py` に schema check (文字列限定) と `template-path` subcommand を追加、`daily-research.sh` がループ内で解決して注入 (`$LINE_TEMPLATE`) する。読めないパスは既定へ fallback する (レポートが出ないより節構成が旧いほうがまし)。テーマ選択 Step 3 問 3 に「line の focus が使い道の定義を別に持つ場合はそちらで判定」の逃し弁を追加する。
4. **edge line を手筋収穫型へ改修する**。読者契約を「朝の読者 (運用者本人) が新しい AI 活用のアイデア — 移植できる手筋と強度の相場観 — を得る」に固定する。専用テンプレート `templates/report-template-edge.md` を新設し、節構成を「何が起きたか (物語本体・事件から開始・異常な数字と当事者の生の引用を主役に) / 盗める手筋 (必須 1〜3 個、無い日は相場観の更新 1 行) / 検証メモ (任意 3 行以内、到達確認の結果のみ) / 機会メモ / ソース (固定 2 節は ctl-016 対象のまま)」とする。「結論」「背景」「この repo への含意」は edge から廃止する。規準への示唆は「（台帳メモ: …）」1 行のみとする。`config.toml` `[tracks.edge]` の focus を目的から書き換える — 採否は「手筋か相場観が盗めるか。迷ったら載せる」、一人称は優先だが必須でない ([unverified] 明示で三人称・二次も可)、崩壊系は限界値の観測として集める (post-mortem 待ちの受動収集をやめる)、新ツールは常識外の使い方なら対象とする。入場条件の正本は `edge-frontier/README.md` で focus はその要約 (同日改訂済み)。
5. **edge playbook を棚卸しする**。`state/edge/playbook.md` (615 行) から台帳設計・概念の輸入・一人称の読み方・反対材料の 4 節を `edge-frontier/docs/notes/criteria-review-input.md` へ移送する (daily run は読まない — 規準見直しの入力)。残すのは方針変更・検証の作法・日本語圏の 3 節 (運用知)。運用者による一括整理であり、run に課す delta 更新規約の違反ではない。

## Review-when

- **2026-09-03 (改修後 7 日)**: 2026-08-28 以降の vault の edge レポート 7 本を運用者が通読し、6 つの失敗型 (①〜⑥) の再発と「盗める手筋」節の形骸化 (移植可能な手筋ゼロで相場観 1 行のみが 4 本以上) を判定する。再発していれば、テンプレート側でなく書き手側 (モデル選択・呼2 の強化) の対策へ切り替える。
- **研究 line (akc / contemplative / aap 等) の「この repo への含意」の質が文体規律 (特に内部参照の 1 行要約義務) で劣化したと運用者が観測したら**: 規律 (3) の適用を line 別に緩める。
- **edge の「迷ったら載せる」で `cases.md` のノイズ (後から読み返して盗めない行) が実害になったら**: 入場の経済を再調整する (正本は `edge-frontier/README.md` 側)。

## Alternatives Considered

### 呼2 clarity レビューの強化だけで直す

span 編集 1 周では①⑥ (節構成・テーマ選択ゲート由来) に届かない。発生源が上流の構造規定にある以上、上流を直すのが先。呼2 の強化は本 ADR でも併用する (決定 2) が単独では不十分。棄却。

### 全 line の節構成も一斉改修する

未決 (今回は見送り)。研究 line は「この repo への含意」が本体という設計 (ADR-0014 決定 7) で、edge とは病理が異なる。文体層のみ共通適用し、節構成は edge で効果を見る。未決 — 再訪条件: 改修後の研究 line レポートで含意節の可読性不足が続いたら。

### レポートをカード型 (3 行の事実 + 異常な数字 + 生の一文 + 手筋 1 個) へ転換し、物語は当たり事例の日だけ書く

相場観の更新は要約でなく物語の手触りが運ぶという判断で、運用者が物語主体を選択した。棄却。

### edge line を廃止して人間の手動収集へ戻す

エッジ事例の出現は日単位のイベントという [ADR-0013](./0013-edge-daily-line.md) の前提は生きており、daily 観測の価値は改修と独立。棄却。

## Consequences

### Positive

- 朝のレポートが repo の履歴なしで読める
- edge から移植可能な手筋が毎日高々 3 個の定型で得られる
- per-track テンプレート機構により今後の line 別節構成が config 1 行で足せる
- edge playbook が運用知 3 節に減り、毎朝の注入と state 更新の対象が軽くなる

### Negative

- 研究 line では内部参照の 1 行要約義務のぶん本文が冗長化しうる
- edge の「迷ったら載せる」で `cases.md` のノイズ率が上がりうる (検証は採用時 on-demand へ移る)
- 共通テンプレと edge テンプレの二重管理が発生する
- 移送先 `criteria-review-input.md` は daily run が読まないため、人間が規準見直しを起動しない限り死蔵されるリスクがある

### Neutral / Follow-ups

- ADR-0014 の Review-when 第 1 項 (2026-08-30 の通読判定) は本 ADR で消化済みとなり、以後の通読判定は本 ADR の Review-when 第 1 項が引き継ぐ
