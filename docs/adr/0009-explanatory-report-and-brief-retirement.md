# ADR-0009: 解説レポートへの転換と 7:00 承認ブリーフの廃止 (ADR-0008 の目的関数を修正)

## Status

Accepted

## Date

2026-08-05

## Context

ADR-0008 (2026-08-04) は目的関数を「この line を今すぐ前に進める、実行可能な手を見つける」に置き、レポートを actionable-tactics note（リード = 手 1〜3 件、各: 手順 / 所要 / 失効条件 / gate 留意）とし、毎朝 7:00 に `morning-brief.sh` が当日ノートの「今すぐ実行可能な手」節を決定論抽出して Slack へ「実装プラン承認リクエスト (N 件)」を送る設計にした。

2026-08-05、初の全 line 走行（akc / contemplative / aap / authorship / ans の 5 line。5 本目の `ans` = attention-not-self は 2026-08-04 に config.toml へのライン追加で導入 — line 集合は config から動的取得のため運用変更であり、ADR-0008 Consequences の「現行 4 line」は当時の値）の後、運用者（唯一の読者）が 2 つの問題を観測した。

1. **承認キュー化**: 全ノートが作業提案で始まり、「返事待ち todo」として Slack に着弾する。実測は、初の定時 7:00 実行（2026-08-05）が 5 ノート・8 件の手を承認リクエストとして送信（`logs/2026-08-05.log`）、前日の手動実行（2026-08-04 09:46）が 8 ノート・3 件（`logs/2026-08-04.log`）。消化が「消火」になり、リサーチの受け取りが負債化した。
2. **前段の説明不足**: ノートが専門用語（例:「weight-consolidation 批判」「text-level distillation」）を説明なしに使い、いきなり各論に入る。主題がそもそも何の論点か・登場する概念・なぜこの repo に関係するかの背景説明が無く、読者がノート単体で内容を理解できない。

一方、リサーチ本文の質（定点観測の差分、一次ソース確認、repo の thesis に触れる反対材料の発見）は高く、per-repo in-context research のエンジン自体は機能していた。壊れているのは出力の枠組みであってエンジンではない、というのが運用者の診断である。

決定は 2026-08-05 の grill-me 面談（対話セッション内。一次記録は本 ADR）で確定した。「期限見逃しの代替通知を作らない」は面談で明示的に受容されたトレードオフである（`/dr-review` への失効日集約案も提示されたが不採用 — `.notes/dr-review-state.json` の記録は導入日 2026-07-29 の 1 件のみで週次習慣は未成立、かつ面談で運用者が `/dr-review` の存在自体を認知していないことが判明したため、手動コマンド前提のセーフティネットは楽観的すぎると判断した）。

## Decision

1. **目的関数を置換する**: 「実行可能な手を見つける」→「repo の前提・問い・立場を動かす外部の動きを見つけ、前提知識ゼロで読める解説レポートとして届ける」。レポートは読み物であり、提案・承認要求・作業手順を書かない。
2. **レポート本文を自由形式にし、5 つの記述規律を課す**（正本 `templates/report-template.md`）:
   - (a) 冒頭に結論 — 今日の動きが repo にどう効くかの総合判断。「変化なし」も根拠付きなら正の成果。
   - (b) 前段の背景解説 — 各論の前に、主題の論点・登場概念・repo との関係を前提知識ゼロの読者向けに数段落で解説。専門用語は初出時に平易に説明。
   - (c) 反対材料 — repo の主張に反する外部知見を最低 1 件本文で扱う（ADR-0008 の前提挑戦パスを維持）。
   - (d) 定点観測の結果を含める。
   - (e) 全 claim に as-of 日付。

   これに伴い、ADR-0008 テンプレートの独立必須節（今すぐ実行可能な手 / 差分と失効チェック / 根拠と新規シグナル / 我々の立場と矛盾・複雑化する知見 / 開いた問い）は節としての義務を解除し、内容は記述規律 (a)〜(e) に吸収する。**「開いた問い」節の廃止により、repo の open-question 語彙への明示接続の義務は消える** — 新しい問いは本文散文に現れうるが、定型的な接続は要求しない（ADR-0002/0003 の知識環流との接点に触れる変更。環流の主経路である wiki ingest とレポート本文は維持される）。
3. **機械検査（ctl-016）の固定節を末尾 2 節に縮退する**: 「機会メモ」（日付付き締切を持つ機会のみ、何を / どこで / 失効日 の 3 行定型、無い日は「なし」）と「ソース」（最低 5 件、run 内解決済み）。`dr_pipeline.py` の `ARTICLE_SECTIONS` を同期する。frontmatter の `actionable:` フィールドは名前を維持し意味を「機会メモ件数」に変更する（現在このフィールドに機械的消費者は無い — `metrics.jsonl` のレコードキーにも含まれない。既存 vault ノートとの frontmatter 互換のため名前だけ温存する）。
4. **7:00 の承認ブリーフを完全廃止する**: `scripts/morning-brief.sh` と brief plist（example / local）を削除し、launchd から unload する。期限見逃しの代替通知は意図的に作らない — 締切はノートの機会メモを読むときに拾う。
5. **エンジンは無変更で維持する**: per-repo cwd 実行・diff-first state 層・citation ゲート・前提挑戦パス・自己汚染ガード・past_topics dedup・ctl-015・metrics.jsonl・repo read-only 三層（ADR-0008 Decision 1/3/4/5/7）。

本 ADR は [ADR-0008](./0008-per-repo-in-context-research.md) の Decision 2（目的関数と actionable-tactics note 形式）と Decision 6（承認ブリーフ）を修正（amend）する。ADR-0008 の他の決定は preserve する。

## Alternatives Considered

### 期限検知時のみ Slack 通知

日付付き失効条件が N 日以内の機会メモがある日だけ通知を鳴らす案（面談では推奨案として提示）。決定論判定のまま通知の信号値を回復できるが、運用者は「頻度・内容を問わず、通知が着弾すること自体」を消したいと判断し、締切見逃しリスクの受容と引き換えに通知経路そのものの廃止を選択した。棄却。

### /dr-review への失効日集約

週次レビュー (`/dr-review`) に「今後 2 週間に失効する機会一覧」を追加する案。`/dr-review` は手動コマンドで運用者は未使用であり、週 1 で打つ習慣を前提にしたセーフティネットは楽観的すぎると判断した。棄却。

### 厳密な節定型の維持

「状況判断 / 定点観測の変化 / 今日見つけたもの / 反対材料 / 新しい問い / 機会メモ / ソース」の 7 節構成を面談中に一度設計したが、運用者が「レポート内容は割と自由でいい」と表明した。機械検査を末尾 2 節に絞り、本文は記述規律ベースの自由形式へ切り替えることを選択。棄却。

### 手の完全廃止（機会メモも置かない）

期限付き機会（例: NeurIPS TTCL 締切 2026-08-29）の記録が散文中に溶け、読者が締切を走査で拾えなくなる。軽量 3 行定型は主として**人間の走査可能性**のために残す（morning-brief 廃止後、この定型を読む機械は ctl-016 の見出し存在チェックだけであり、将来抽出器を再導入する場合の形式予約を兼ねる）。棄却。

## Consequences

### 良い面

- 毎朝の Slack 通知が消え、レポートは読む行為で完結する。返答義務・消火感が構造的に消える。
- リサーチ本文の質（定点観測の差分・一次ソース確認・反対材料の発見）を担うエンジン部分は無変更のため、既存の強みをそのまま引き継ぐ。

### 悪い面

- 期限付き機会の発見はノートを読む習慣に依存する。読まない日が続けば締切を見逃す — 面談で明示的に受容したトレードオフ。
- 背景解説の義務によりノートは長くなり、執筆 turn とコストを消費する（初回全 line 走行の実測は 5 line 合算で total_cost 11.44 USD 相当 / 約 41 分 / 171 turns — `metrics.jsonl` 2026-08-05。Max プランのため従量課金は発生しないが、本変更はこれを押し上げる方向。max-turns 55 / 25 分 timeout 内で吸収する想定で、初週の metrics で実測確認する）。
- ctl-016 の検査範囲が縮む: 本文の記述規律（結論・背景解説・反対材料）の充足は機械検査できず、人間 consumer の判断に戻る（ADR-0006 の路線と整合）。
- ADR-0008 の Consequence にあった「行動ループ（ブリーフ → 承認 → gate 済み deploy）が閉じる」は失われる。取り込みは運用者がノートを読んで自発的に repo セッションを開く形になる。

### 中立 / 追跡事項

- vault ノート frontmatter の `actionable:` は「機会メモ件数」の意味に変わる（フィールド名は既存ノートとの互換のため温存。機械的消費者は現在無い）。
- 削除した `morning-brief.sh` / brief plist は git history から復元可能。
