# {topic_title}

（この line のレポートは**朝の読者が新しい AI 活用のアイデアを得るための読み物**である。
主役は物語と手筋。記述規律は 4 点:

1. **事件から始める**: 第一文は起きたことで始める。この repo・台帳・過去レポート・
   規準への言及で書き始めない。「結論」「背景」「この repo への含意」の節は作らない —
   背景説明は物語に織り込み、含意は「盗める手筋」が担う。
2. **異常な数字と当事者の生の引用を主役に**: 相場観を動かすのは要約ではなく
   手触りである。当事者の一文は原文のまま引く。
3. **一文一命題**: 挿入句の入れ子・文中太字の多用・圧縮文を書かない。
   専門用語は初出時に平易に。
4. **検証の実況を本文に書かない**: 括弧の認識論注記（「断定しない」「本 run で検算」等）は
   本文 2 箇所まで。到達確認の結果は「検証メモ」節に隔離する。

本文の目安は 3,000 字以内。規準・台帳設計への示唆が生まれた日は、ソース節の直前に
`（台帳メモ: …）` を 1 行だけ置いてよい — それ以上のメタ議論は書かない。
末尾の「機会メモ」「ソース」の 2 節は下記の固定見出し・形式で書く — 機械検査
(ctl-016) の対象である。）
