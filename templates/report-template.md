# {topic_title}

（本文は自由形式。節立て・見出しは内容に合わせて自分で設計してよい。
ただし以下の記述規律を必ず満たすこと:

1. **冒頭に結論**: 今日の外部の動きがこの repo の主張・問いにどう効くかの総合判断を
   数文で書く。提案・承認要求は書かない。「変化なし」の日はそれを根拠付きで書く —
   それも正の成果である。
2. **前段の背景解説**: 各論に入る前に、今日の主題がそもそも何の論点か・登場する概念・
   なぜこの repo に関係するかを、**前提知識ゼロの読者向けに数段落で解説**する。
   専門用語は初出時に平易に説明する。読者はこのノート単体で内容を理解できなければ
   ならない。
3. **反対材料**: repo の主張に反する・都合の悪い外部知見を最低 1 件、本文中で扱う。
   見つからない日は「反証方向の検索を N 回実行（クエリ: ...）したが見つからなかった」と
   明記する — 無理にひねり出さない。
4. **定点観測の結果**: watched source ごとの「変化なし / 何が変わったか（日付）」と、
   失効条件に達していた過去の前提の再検証結果（まだ有効 / 反故になった）を
   本文のどこかに含める。「反故になった」は隠さず書く。
5. すべての claim に as-of 日付。一次ソースを WebFetch で確認済みの事実だけを事実として
   書き、二次情報は「〜と報じられている」と区別する。

末尾の「機会メモ」「ソース」の 2 節だけは下記の固定見出し・形式で書く —
機械検査 (ctl-016) の対象である。）
